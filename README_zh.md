# Wiki Copilot

[English](README.md) | [简体中文](README_zh.md)

Wiki Copilot 是一个面向持久化 LLM Wiki 的 Obsidian 知识库问答插件。它把知识库理解为结构化系统：规则文件描述本地约定，Wiki 页面沉淀整理后的知识，原文 Markdown 提供可追溯证据。

配置模型后，两种检索模式都会先让模型生成数量受限的词法检索短语，并始终保留原问题。快速模式使用 3～6 条变体搜索整理好的 Wiki 索引；精准模式使用 4～10 条变体扫描全部可检索 Markdown 正文，再提取相关度最高的章节。插件不依赖向量嵌入服务。

## 功能

- 自动识别规则、索引、专题、概念、摘要、稳定原文和待处理原文等知识角色。
- 快速模式只搜索整理后的 Wiki 片段，并进行 Wikilink 一跳扩展。
- 精准模式扫描配置范围内的全部 Markdown 正文，覆盖更完整。
- 保留型号、文档号、路径、复合词和驼峰标识符。
- 对“所有、全部、列出、清单”等问题扩大相关文档族的候选范围。
- 回答使用 `[S1]` 等来源标记，可跳转到对应 Obsidian 笔记和标题。
- 支持流式回答、停止生成、增量 Markdown 渲染及非流式兼容模式。
- API 密钥保存在 Obsidian 安全存储中。
- 不依赖 Node.js、Electron、本地服务或原生数据库，同时支持桌面端与移动端。

## 安装与使用

要求 Obsidian 1.13.0 或更新版本。

手动安装时，将以下文件复制到知识库配置目录的 `plugins/wiki-copilot/`：

- `main.js`
- `manifest.json`
- `styles.css`

然后在 Obsidian 的第三方插件设置中启用 **Wiki Copilot**。

首次使用：

1. 打开 Wiki Copilot 设置。
2. 选择 DeepSeek、OpenAI 或其他 OpenAI 兼容服务。
3. 选择模型并填写 API 密钥；无鉴权的自定义本地服务可以留空。
4. 选择“精准（推荐）”或“快速”检索，再从侧栏按钮或命令面板打开 Wiki Copilot。

未完整配置模型时，发送问题会返回本地检索结果；配置完成后会生成带引用的模型回答。

## 检索流程

```text
问题
  │
  ├─► 模型生成受约束的检索短语（失败时使用原问题）
  │
  ├─► 快速模式
  │     ├─► 原问题 + 3～6 条检索变体
  │     └─► 搜索索引、专题、概念、摘要及其他 Wiki 片段
  │             ├─► 多查询词法检索与合并排序
  │             └─► Wikilink 一跳扩展
  │
  └─► 精准模式
        ├─► 原问题 + 4～10 条检索变体
        ├─► 逐份检查全部可检索 Markdown 正文
        ├─► 保留高相关文件并提取相关章节
        └─► 精确标识符过滤、排序和上下文裁剪
```

两种模式共享相同的问题理解入口，区别在搜索范围与深度。快速模式依赖较小且价值较高的 Wiki 索引；精准模式接受更长等待，逐份检查 Markdown 正文。扫描过程中不会建立第二份全库正文索引，也不会同时把全部文件留在内存中。

## 对话上下文

- 检索规划最多使用最近 4 条对话、8,000 个字符，用于理解省略的主体、指代和范围。
- 最终回答最多使用最近 10 条对话、24,000 个字符。
- 当前问题明确指定的新主体或范围始终优先，不会被旧对话覆盖。
- 检索规划阶段不发送知识库正文；最终回答阶段只发送本轮选中的证据片段。

## 知识库自动识别

插件面向 Karpathy `llm-wiki` 理念，不依赖某一套固定目录。它会综合以下信号识别知识层、原文层和待处理层：

- 根目录的 `AGENTS.md`、`CLAUDE.md` 等规则文件。
- `wiki`、`knowledge`、`kb` 等常见知识层名称。
- `topics`、`concepts`、`summaries` 等知识页角色。
- `source`、`sources`、`raw` 等原文层名称。
- `processed`、`curated`、`verified`、`pending`、`inbox` 等状态语义。
- 规则文件中以反引号标出的自定义路径及其文字说明。

这些规则属于内部自动策略，无需用户设置。规则文件只指导结构识别与查询，不作为事实证据。

## 隐私与安全

- 索引数据不会发送给模型服务商。
- 手机端缓存保存在设备本地 IndexedDB；桌面端缓存保存在知识库配置目录。
- 发送给模型的内容仅限检索规划所需的问题与近期对话，以及最终回答所需的命中片段、问题和近期对话。
- 原文和 Wiki 内容均被视为不可信数据，系统提示会要求模型忽略来源中夹带的指令。
- API 密钥保存在 Obsidian 安全存储中，不写入插件 `data.json`。
- 当前版本不会自动修改 Wiki 或原文。

## 当前限制

- 当前没有向量嵌入或语义向量召回；同义表达能力主要来自模型生成的受约束检索词、已维护的 Wiki、别名、标题和链接网络。
- 精准模式需要读取全部可检索 Markdown，知识库越大、设备存储越慢，等待时间越长。
- 会话只保存在当前侧栏实例中，重载插件后不会恢复。
- 流式请求依赖服务端支持 SSE 与 WebView 跨域访问；不兼容的服务可以使用非流式兼容模式。
- 当前版本不会自动把高质量回答写回 Wiki。

## 路线图

### 待办一：问答提炼并保存

- 将用户确认的高质量问答提炼为可复用的 Wiki 草稿，而不是直接保存聊天原文。
- 保存前提供目标页面、标题、正文和引用预览，允许用户修改或取消。
- 保留来源引用与证据到结论的映射，只写入 Wiki 层，不自动修改原文。
- 支持新建页面和合并到已有页面，并处理覆盖、冲突和重复内容。

### 待办二：向量混合检索

- 增加可选的向量语义召回，补充同义表达和关键词不重合的内容。
- 保留现有关键词、精确标识符、Wikilink 和 Wiki 分层检索，并与向量结果融合排序。
- 优先考虑移动端索引体积、构建耗时、缓存恢复、隐私边界和服务配置体验。

## 开发

```bash
pnpm install
pnpm lint
pnpm test
pnpm build
pnpm check
pnpm deploy
```

`pnpm deploy` 默认把构建产物复制到源码同级的 `obsidian/.obsidian/plugins/wiki-copilot/`。如需部署到其他知识库，可设置 `WIKI_COPILOT_VAULT_ROOT`：

```powershell
$env:WIKI_COPILOT_VAULT_ROOT = "C:\path\to\vault"
pnpm deploy
```

发布第三方插件时，GitHub Release 需要包含 `main.js`、`manifest.json` 和 `styles.css`。
